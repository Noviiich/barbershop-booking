# ADR-004: доставка через PostgreSQL outbox

Статус: Accepted. Дата: 2026-09-11.

## Контекст

Нельзя атомарно записать Booking в локальную БД и выполнить HTTP в Яндекс. Падение процесса между этими действиями теряет синхронизацию при наивной реализации.

## Решение

Booking + audit + receipt + outbox фиксируются одним commit. Отдельный worker доставляет события at-least-once, используя lease, короткий claim через SKIP LOCKED и owner token. PostgreSQL хранит событие и состояние доставки; отдельного Redis/Celery/Kafka на старте нет. Повторы, dead-letter/parked, сериализация по booking, schema version событий и reconciliation обязательны.

Входящие синхронные команды сохраняют receipt вместе с эффектом; для согласованных асинхронных событий используется durable inbox до ACK. Детали порядка, coalescing и неизвестного исхода HTTP — в [yandex-integration](../architecture/yandex-integration.md).

## Альтернативы

HTTP внутри транзакции удерживает locks и не решает распределённую атомарность. Только callback после commit теряет событие при crash. Публикация в брокер после commit имеет тот же разрыв без outbox. Event sourcing создаёт ненужное обязательство восстанавливать домен из событий.

## Последствия

Локальная отмена устойчива при недоступном канале; внешняя проекция может отставать. Worker, housekeeping и мониторинг нужно реализовать и поддерживать. Локальный fencing защищает cursor, но не отменяет запрос в сети: внешнее version fencing или сверка нужны отдельно. При росте объёма транспорт можно заменить с сохранением outbox.

## Проверка

AUD-01, OUT-01, OUT-02, REC-01; PR-07/15/19/20. Команда: `rtk proxy uv run pytest tests/integration/test_outbox.py tests/faults/test_delivery.py`. Критерий: committed событие не пропадает, повтор допустим, протухший owner не подтверждает чужую доставку, последнее состояние сходится при восстановлении связи.
