# Архитектурные решения

Дата базовой версии: 2026-09-11. `Accepted` означает принятое проектное решение, а не реализованную функцию. `Conditional` означает выбранный подход с явно указанным условием активации.

| ADR | Статус | Решение |
| --- | --- | --- |
| [0001](0001-backend-stack.md) | Accepted | Python/Django/DRF/PostgreSQL, модульный монолит |
| [0002](0002-postgres-consistency.md) | Accepted | Защита интервалов в БД и единый порядок блокировок |
| [0003](0003-idempotent-commands.md) | Accepted | Durable receipts, версии команд и определённое окно повторов |
| [0004](0004-outbox-and-sync.md) | Accepted | Transactional outbox/inbox, worker без брокера |
| [0005](0005-booking-lifecycle.md) | Accepted | Немедленное подтверждение, терминальные исходы, атомарный перенос |
| [0006](0006-time-and-calendar.md) | Accepted | UTC-моменты, IANA календарь, полуоткрытые интервалы |
| [0007](0007-yandex-boundary.md) | Conditional | Яндекс как канал команд и проекция; запуск после проверки контракта |
| [0008](0008-operations-and-security.md) | Accepted | Проверяемое восстановление, минимизация данных и эксплуатационные ограничения |

Новый ADR содержит контекст, решение, альтернативы, последствия и проверку. Существенное изменение принятого решения оформляется новым номером с `Supersedes`; старый документ получает ссылку `Superseded by`. Оформление и реализация делаются по [roadmap](../roadmap.md). Подтверждение тестами описано в [testing-strategy](../testing-strategy.md).
