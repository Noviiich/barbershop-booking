# ADR-005: lifecycle и отмена

Статус: Accepted. Дата: 2026-09-11.

## Контекст

Нужно однозначно определить момент подтверждения, освобождения слота и терминальные исходы. Яндекс может быть недоступен, поэтому его состояние не должно управлять локальным lifecycle.

## Решение

Новая запись сразу CONFIRMED после commit. Переходы в CANCELLED, COMPLETED и NO_SHOW терминальны. Отмена сохраняет историю и освобождает время атомарно. COMPLETED/NO_SHOW сохраняют историческое ограничение пересечений; исход отмечает сотрудник после планового окончания.

Перенос меняет время той же записи в одной транзакции с expected_version и увеличением версии. Это событие, а не самостоятельный статус. Точные guards/no-op — в [domain-model](../architecture/domain-model.md). MVP не включает оплату, holds, ручное подтверждение, смену мастера и восстановление terminal.

## Альтернативы

PENDING до ответа Яндекса делает внешнюю систему арбитром. Удаление при отмене теряет историю и мешает дедупликации. Отменить и создать в разных транзакциях для переноса может оставить клиента без исходной записи. Статусы для ещё не реализованных платежей/TTL увеличивают число непроверенных переходов.

## Последствия

Простой конечный автомат; неподтверждённые временные резервы отсутствуют. Добавление holds потребует отдельного ADR: durable expiry, идемпотентного освобождения, гонки confirm/expire и предиката exclusion без `now()`. Исправление ошибочного terminal не доступно через общий редактор.
