# ADR-006: UTC и календарь филиала

Статус: Accepted; часть о буферах superseded by ADR-009. Дата: 2026-09-11.

## Контекст

Локальная дата, время визита и длительность — разные понятия. Фиксированное смещение не описывает историю/изменения зоны и DST. Сервер может находиться в другой timezone.

## Решение

Моменты визита — UTC `timestamptz`, API — RFC 3339 с offset; IANA timezone филиала и её снимок записи хранятся отдельно. Регулярные смены определяются в местном календаре. Интервалы полуоткрытые `[)`, длительность измеряется в прошедших секундах. Часть первоначального решения о буферах заменена [ADR-009](0009-remove-service-buffers.md).

Несуществующие локальные времена отклоняются, неоднозначные требуют явного offset/fold; правила расписания на таких датах уточняются исключением. Timezone сервера не влияет на результат. Смена timezone/tzdata не сдвигает сохранённые UTC-моменты. Правила горизонта, полуночи и clock описаны в [domain-model](../architecture/domain-model.md).

## Альтернативы

Naive datetime зависит от окружения. Только offset не хранит календарных правил зоны. Только локальное время неоднозначно при переводе часов. Хранение начала плюс постоянно читаемая текущая длительность услуги ретроактивно меняет визиты.

## Последствия

Требуются отдельные поля для timezone и неизменяемых снимков, тесты DST даже для стартовой Москвы, контролируемые обновления tzdata и календаря. Отсутствие изменения часов в первой зоне не оправдывает зашитый offset.

## Проверка

TIME-01, AVL-01, DB-01; PR-05/06/10. Команда: `rtk proxy uv run pytest tests/unit/test_time.py tests/integration/test_availability.py`. Критерий: один UTC-момент независимо от timezone процесса, корректные полночь/DST и допустимые соседние интервалы.
